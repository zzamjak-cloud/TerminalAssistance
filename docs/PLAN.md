# Terminal Assistance — 개발 계획

## 1. 기존 프로그램(Terminal Image Paste) 분석

### 구조
- Windows 전용 PowerShell 상주 앱(835줄 단일 스크립트) + 설정 GUI + 설치/제거 스크립트.
- Win32 API(P/Invoke) + UI Automation + WinForms 오버레이 조합.

### 핵심 동작
1. **Alt+V 후킹**: Windows Terminal 포커스 중 Alt+V 접수 → 클립보드 이미지를 `%TEMP%\claude_img` 에 PNG 스냅샷 → Alt+V 재주입(네이티브 첨부 유지).
2. **칩 매핑**: UIA 로 화면의 `[Image #N]` 텍스트를 읽어 `{N → 이미지 경로}` 매핑.
3. **썸네일 오버레이**: 붙여넣은 직후/칩 클릭 시 몇 초간 해당 위치 위에 썸네일 표시.
4. **드롭 패드**: WT 창마다 우상단에 드롭 존 표시. 파일/브라우저 이미지/URL/가상파일 스트림 드롭 → 클립보드 경유 자동 첨부. 클립보드 백업·복원 포함.
5. **원클릭 캡처**: 패드 클릭 → `ms-screenclip:` 실행 → 캡처 완료 감지 → 자동 첨부.

### 잘된 점 (계승할 가치)
- 이벤트 기반 경량 설계(평소 UIA 0회, 폴링 최소화) — 성능 강박이 코드 전반에 배어 있음.
- 클립보드 백업/복원, 다중 드롭 큐, 대형 이미지 자동 축소, DPI 인식 등 엣지 케이스 처리가 치밀함.
- 이미지 히스토리(최근 10개 재첨부) 개념.

### 한계 (새 프로젝트의 출발점)
- **외부에서 터미널을 훔쳐보는 구조**: UIA 텍스트 스크래핑, 키 재주입, z순서 가림 판정 등 취약한 우회 기법에 의존. Windows Terminal 렌더링이 바뀌면 깨짐.
- **Windows 전용**: Win32 API 에 전면 의존, macOS 이식 불가.
- **터미널 상태를 알 수 없음**: 어떤 터미널이 무슨 작업 중인지, 끝났는지 알 방법이 없음.
- **확장 불가**: 프로젝트 관리, 명령 프리셋 같은 기능을 얹을 자리가 없음.

**결론**: 터미널 "밖"에서 보조하는 방식은 한계가 명확. 터미널 자체를 호스팅하는 앱으로 전환하면
이미지·상태·프로젝트 모두 1급 시민으로 다룰 수 있다.

## 2. 새 비전: Terminal Assistance

> AI(Claude Code 등) 시대의 멀티 프로젝트 터미널 워크스페이스.
> 터미널을 감싸는 게 아니라, 터미널을 품는다.

### 핵심 기능 (MVP)
| 기능 | 설명 |
|---|---|
| 프로젝트 레지스트리 | 프로젝트(이름·경로·색상)를 등록해 두고 클릭 한 번으로 해당 경로의 터미널 세션 열기/전환 |
| 멀티 세션 | 프로젝트당 여러 터미널 세션, 사이드바에서 즉시 전환 (Cmd/Ctrl+1~9) |
| 상태 시각화 | 세션별 실행중(●애니메이션)/대기/완료(파란 배지)/종료(빨강) 실시간 표시 + 완료 알림 |
| 명령 프리셋 | 전역/프로젝트별 자주 쓰는 작업 지시를 등록, 클릭=실행, Shift+클릭=입력만 |
| 이미지 첨부 | 클립보드 이미지 붙여넣기(Cmd/Ctrl+V)·드래그앤드롭 → PNG 저장 후 경로 자동 입력, 하단 스트립에 썸네일 히스토리 |
| 크로스 플랫폼 | macOS / Windows 동일 코드 (Electron + node-pty + xterm.js) |

### 기술 선택
- **Tauri 2 + xterm.js + portable-pty(Rust)**: 시스템 WebView(mac WKWebView / win WebView2) 기반이라
  상주 앱으로서 메모리 점유가 낮고(수십 MB 수준) 바이너리도 ~10MB. PTY 를 Rust 네이티브 스레드로
  직접 소유하므로 상태 감지가 정확하고 가볍다. "터미널을 대체하는 상시 구동 도구"라는 목표에 부합.
- Electron 대비: 개발 생태계는 Electron 이 성숙하지만 Chromium 동봉(200MB+)의 상시 비용이 크다.
  렌더러를 순수 웹(번들러 없음)으로 유지해 백엔드 교체 가능성을 열어 둠 (`api.js` 어댑터로 격리).
- 빌드 무의존 렌더러(번들러 없음): 유지보수 단순화, 기여 진입장벽 최소화.
- 자동 업데이트: `tauri-plugin-updater` + GitHub Actions(태그 푸시 → 릴리즈 + latest.json).

### 상태 감지 설계
1단계(MVP): PTY 출력 활동 휴리스틱 — 출력 수신 시 busy, 800ms 무출력 시 idle 전환.
3초 이상 busy 후 idle 이 되면 "완료"로 승격, 비활성 세션이면 배지+데스크톱 알림.
2단계(로드맵): OSC 133 셸 통합(명령 시작/종료 마커), Claude Code 훅 연동으로 정확도 향상.

### 아키텍처
```
src/
├── main/            # Electron 메인 프로세스
│   ├── main.js      # 앱 수명주기, 윈도우
│   ├── pty-manager.js  # 세션 생성/입출력/상태 머신
│   ├── store.js     # 프로젝트·프리셋·설정 JSON 영속화
│   └── ipc.js       # IPC 계약 (렌더러 ↔ 메인)
├── preload/preload.js  # contextBridge 안전 노출
└── renderer/        # 순수 웹 (번들러 없음)
    ├── index.html / styles.css
    ├── app.js       # 상태·라우팅·키바인딩
    ├── terminal-view.js  # xterm 연결, 이미지 붙여넣기/드롭
    ├── sidebar.js   # 프로젝트/세션 목록 + 상태 표시
    └── presets.js   # 명령 프리셋 바
```

### 성능 원칙 (기존 프로그램에서 계승)
- 폴링 최소화: 상태 체크는 메인 프로세스 500ms 단일 타이머, 세션 수와 무관하게 O(n) 맵 순회만.
- PTY 출력은 xterm 에 직결(가공 없음). 비활성 세션도 xterm 버퍼가 백그라운드 유지 — 전환 시 리플로우 없음.
- 이미지 썸네일은 첨부 시 1회 생성 후 dataURL 캐시.

## 3. 로드맵
- **Phase 1 (MVP, 이 저장소 초기 커밋)**: 위 핵심 기능 전부.
- **Phase 2**: OSC 133 셸 통합 상태 감지, 분할 뷰(한 화면 2~4 세션), 세션 복원, 검색(Cmd+F).
- **Phase 3**: 원클릭 화면 캡처 첨부(mac `screencapture -i` / win `ms-screenclip:`), 프리셋 변수(`{branch}` 등), 프리셋 순차 실행(파이프라인).
- **Phase 4**: electron-builder 배포(dmg/exe), 자동 업데이트, 테마.
